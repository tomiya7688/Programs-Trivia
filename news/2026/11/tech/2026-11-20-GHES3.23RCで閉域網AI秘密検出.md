# GHES 3.23 RC、閉域網のCopilot CLIとAI秘密検出が来るんだぜ！

- **出来事の日付**: 2026-11-19（3.23.0-rc.1公開）／2026-11-20（GitHub Changelogで発表）
- **執筆日**: 2026-11-26
- **区分**: Tech News / セキュリティ・開発基盤
- **公開状態**: GHES 3.23はRelease Candidate。AI secret detectionとOAuth token expirationはPublic Previewなんだぜ

## GitHub Enterprise Serverが3.23の候補版になったんだぜ！

GitHubが2026年11月20日、オンプレミス環境向けの **GitHub Enterprise Server（GHES）3.23 Release Candidate** を発表したんだぜ。リリースノート上の版は3.23.0-rc.1で、日付は11月19日なんだぜ。

今回の目玉は、単なる画面の追加だけじゃないんだぜ。**閉域網でCopilot CLIを使えるようにすること、外部ネットワークへ出さずにAIで秘密情報を検出すること**が大きな変化なんだぜ！

## 閉域網でもCopilot CLIが正式提供なんだぜ！

GHES 3.23では、GitHub Enterprise Cloudへ接続できない切断環境・エアギャップ環境でも、**GitHub Copilot CLIが一般提供（GA）**になるんだぜ。

管理者がGHES上でモデルプロバイダーを一度設定すれば、利用者はGHESの認証情報を使ってCopilot CLIを利用できるんだぜ。

クラウドへ接続できない社内ネットワークでも、エージェント型のコーディング支援を使える方向なんだぜ。これはPublic Previewではなく、GHES 3.23のリリースノートではGAとして記載されているぜ。

## 閉域網でもAIで秘密を探せるんだぜ！？

GitHub Secret Protectionを利用しているEnterpriseでは、GHES上で非構造化された秘密情報をAIで検出できるようになるんだぜ。

- モデルはGHESアプライアンス内で動く自己完結型
- GPUは不要で、アプライアンスのCPU上で実行
- ホスト型LLMや外部への通信を必要としない
- エアギャップ環境でも利用できる設計

「秘密を探すために、秘密を外部のAIへ送る」なんて心配を減らせる方向なんだぜ。

ただし、これは**Public Preview**なんだぜ。機能や挙動が変わる可能性があり、GitHub Secret Protectionの利用も前提なんだぜ。正式版と同じつもりで本番環境へ入れるのは早いぜ。

## 悪意あるパッケージの情報もnpm以外へ広がるんだぜ！

GitHub Advisory Databaseが、既存のnpmに加えて次のエコシステムの既知の悪意あるパッケージ情報を扱うようになるんだぜ。

- PyPI
- Maven
- RubyGems
- NuGet
- Go
- Rust
- Composer

OpenSSFのmalicious-packagesリポジトリからアドバイザリを取り込むことで、パッケージの供給網を横断して危険な配布物を見つけやすくするんだぜ。

ただし、これは**登録済みの悪意あるパッケージ情報を見つける仕組み**なんだぜ。すべての不正パッケージを事前に見抜けるわけではないし、依存関係の確認やロックファイルの管理が不要になるわけでもないぜ。

## Dependabotは更新PRを3日待つんだぜ！

GHES 3.23では、Dependabotが新しいパッケージ版を見つけても、レジストリで少なくとも**3日間公開されてから**バージョン更新PRを作るようになるんだぜ。

公開直後のパッケージが、後からマルウェアや重大な不具合だと判明することもあるんだぜ。少し時間を置くことで、コミュニティが異常に気づく猶予を作るわけだぜ。

もちろん、3日待てば安全が保証されるわけじゃないんだぜ。緊急のセキュリティ修正を急ぐ場合には、運用上の優先順位も考える必要があるぜ。

## GitHub CLIのworktree操作も入るんだぜ！

GHES 3.23では、GitHub CLIを使ってIssueやPull Requestをチェックアウトするときに、Git worktreeを作成し、作業が終わったら削除できるようになるんだぜ。

同じリポジトリで複数の作業を並行して進めるときに、ブランチごとの作業ディレクトリを切り替える手間を減らせるんだぜ。AIエージェントを並列で動かす開発フローにも相性がよさそうだぜ。

## OAuthアプリのトークンにも有効期限が来るんだぜ！

OAuthアプリ向けには、アクセストークンを**8時間で期限切れ**にし、リフレッシュトークンで新しいアクセストークンを取得する仕組みが加わるんだぜ。

- 新しく作るOAuthアプリでは期限付きトークンが既定
- 既存アプリではオプトイン
- `scope=offline_access` を使った段階的なテストも可能
- この機能はPublic Preview

既存クライアントがリフレッシュトークンを保存・利用できるようにしてから必須化しないと、ログインが壊れる可能性があるんだぜ。移行手順を確認してから切り替えるんだぜ。

## Release Candidateを本番へ入れてはいけないんだぜ！

ここは特に重要なんだぜ。GitHubのリリースノートは、RCを**テスト環境専用**としていて、本番環境へインストールしないよう明記しているんだぜ。

- サポート対象の旧バージョンからRCへアップグレードできない
- RCからGA版へアップグレードできず、hotpatchも使えない
- RCにはGA版に含まれるすべてのセキュリティ修正が入っているとは限らない
- アップグレード時にカスタムFirewallルールが削除される既知の問題があるんだぜ。
- セルフホストRunnerは最低でも2.337.0が必要で、自動更新を無効にしたephemeral runnerはインスタンス更新前に手動で上げる必要があるんだぜ。

だから、今回のRCは**機能を試すための検証環境向け**なんだぜ。既存の本番インスタンスをそのまま更新するためのものではないぜ。

## だからなんだぜ

GHES 3.23は、**閉域網でのCopilot CLI、AIによる秘密検出、悪意ある依存パッケージの検出、Dependabotの待機期間、Git worktree、OAuthトークンの短命化**をまとめて進める候補版なんだぜ。

ただし、Copilot CLIはGAでも、AI秘密検出とOAuth期限付きトークンはPublic Preview。さらにGHES 3.23自体もRCなんだぜ。正式版と混同せず、必ずテスト環境で試すんだぜ！
