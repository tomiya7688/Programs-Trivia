# CodeQL 2.27.4、誤検知を減らしてパックの外も守るんだぜ！

- **掲載日（執筆日）**: 2026-11-05
- **発表日**: 2026-11-04
- **区分**: Tech News / 静的解析・セキュリティ
- **対象**: CodeQL 2.27.4 / GitHub code scanning

## バグを見つける側にも、直すところがあるんだぜ！

GitHubが11月4日に、静的解析エンジン**CodeQL 2.27.4**の変更点を公表したんだぜ。

「検出件数が多いほど優秀なんだぜ？」と思ったら要注意なんだぜ。実際には**安全なコードを危険と誤認する警告（誤検知）**も、開発者の確認時間を奪うんだぜ。

今回の更新では、C/C++、Rust、Java/Kotlinのクエリ精度が改善されたんだぜ。

## C++のポインタ演算まで疑っていたんだぜ！？

主な変更点はこうなんだぜ。

- **C/C++**：`std::byte*`バッファへの意図的なポインタ演算が、`cpp/suspicious-pointer-scaling`に誤検知されなくなったんだぜ。`[[maybe_unused]]`付きの変数も未使用変数の警告対象から外れるぜ。
- **Rust**：制御されないメモリ確保サイズ、ログインジェクション、平文ログ出力に関するクエリで誤検知が減ったんだぜ。
- **Java/Kotlin**：ログインジェクションやパスインジェクションを調べる際、JDKや複数の定番ライブラリによるサニタイズ・ガードをより正しく認識するんだぜ。

単純に検出を弱めたというより、**意味のある防御処理を理解してノイズを減らす**方向なんだぜ。

## 解析ツールの配布物にも境界があるんだぜ

CLIでは、クエリパックをまとめたり公開したりする際に、シンボリックリンクを解決して**パックのルート外を指すファイルを除外し、警告する**ようになったんだぜ。おいおい、解析用ツールでもファイルの境界確認は欠かせないんだぜ！

JVMの警告や初期化エラーも標準エラー出力へ移され、JSONなどの機械可読な標準出力に混ざりにくくなったぜ。

一部の正規表現関連クエリでは**CWE-730のメタデータタグを外す**修正も行われたんだぜ。これはそのクエリ自体の削除や、対象の脆弱性が解決したという意味じゃないんだぜ。

## まだ注意点もあるんだぜ

GitHub.comのcode scanningには新しいCodeQLが自動展開されるとGitHubは案内しているんだぜ。一方、GitHub Enterprise Serverでは**3.24で同梱予定**で、古いGHESでは手動アップグレードが必要な場合があるぜ。

誤検知が減っても、**脆弱性が全部見つかるわけじゃない**んだぜ。静的解析はレビューやテストの代用品じゃなく、合わせて使うものなんだぜ。

## だからなんだぜ

静的解析の価値は警告の数じゃなく、**本当に調べるべきコードへ開発者を導けるか**なんだぜ。C++やRustの警告に悩まされていたら、CodeQLのバージョンを確認してみるといいぜ！
