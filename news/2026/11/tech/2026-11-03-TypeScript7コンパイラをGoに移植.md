# TypeScriptのコンパイラがGo製になったんだぜ！ しかも約10倍速いんだぜ！

- **掲載日**: 2026-11-03
- **正式公開日**: 2026-07-08
- **区分**: Tech News / プログラミング言語・開発ツール
- **対象**: TypeScript 7.0
- **補足**: 7月のリリースを11月に振り返る記事なんだぜ

## TypeScriptなのに、作っているのはGoなんだぜ！？

Microsoftが2026年7月8日、**TypeScript 7.0**を正式リリースしたんだぜ。

最大の変化は、TypeScriptの**コンパイラや言語サービスの実装をGoに移植したネイティブ版**になったことなんだぜ。

「えっ、TypeScriptでプログラムを書けなくなったんだぜ？」と思ったら違うぜ。

TypeScriptは今までどおり書けるし、JavaScriptへ変換するという目的も変わらないんだぜ。**変わったのは処理する側の実装**なんだぜ。

## どうしてGoで速くなるんだぜ？

TypeScript 6以前のコンパイラは、TypeScript自身で実装し、JavaScriptにコンパイルして実行していたんだぜ。

TypeScript 7では、既存のコンパイラの構造や型チェックの規則を保つことを重視しながら、Goへ**移植（native port）**したんだぜ。

単に言語名を変えただけじゃないんだぜ。

- ネイティブコードとして動かすんだぜ
- メモリ共有を使った並列処理ができるんだぜ
- 解析や出力の工程を最適化したんだぜ

という複数の改善が効くんだぜ。

だから、**「Goという言語なら何でも10倍速い」わけではない**んだぜ。処理系の作り方全体が変わっているんだぜ。

## どれくらい速いんだぜ？

Microsoftの公式発表に載っている、TypeScript 6と7のフルビルド比較はこんな感じなんだぜ。

| プロジェクト | TypeScript 6 | TypeScript 7 |
| --- | ---: | ---: |
| VS Code | 125.7秒 | **10.6秒** |
| Sentry | 139.8秒 | **15.7秒** |
| Playwright | 12.8秒 | **1.47秒** |

公式説明では、典型的なフルビルドで**8〜12倍程度**の高速化が見込まれるとしているんだぜ。

おいおい、分単位のビルド待ちが秒単位になるんだぜ！

ただしこれはMicrosoftが公開した特定プロジェクトでのベンチマークなんだぜ。どのコードでも必ず10倍になるという保証ではないぜ。

## でも互換性はチェックするんだぜ

使うだけなら通常どおり、

~~~shell
npm install -D typescript
npx tsc
~~~

という形でTypeScript 7を導入できるんだぜ。

でも注意点があるぜ。**TypeScript 7.0には、従来のTypeScriptコンパイラAPIに相当する公開APIがまだ含まれない**んだぜ。

つまり、`tsc`でコンパイルする仕事と、`typescript`パッケージをプログラムから直接呼び出す仕事は別なんだぜ。

型チェックツールなどが従来APIに依存している場合は、移行のための互換パッケージ **`@typescript/typescript6`** を併用する方法が公式に案内されているぜ。

IDEの言語サーバーもLSPに対応したんだぜ。エディタの連携状況は使っている環境ごとに確認するぜ。

## そもそも、プログラミング言語とコンパイラは別なんだぜ

ここが一番のトリビアなんだぜ。

~~~text
人間がTypeScriptで書くんだぜ
    ↓
Goで実装されたコンパイラが読むんだぜ
    ↓
JavaScriptを出力するんだぜ
~~~

なんだぜ。

**プログラムを書く言語と、その言語を処理するプログラムの実装言語は同じである必要がない**んだぜ。

コンパイラを自分自身の言語で書く「セルフホスティング」も面白いけど、実装言語を変えることで性能や保守の選択肢を広げる道もあるんだぜ。

## だからなんだぜ

**TypeScriptは言語の使い方を大きく変えずに、コンパイラの内側を入れ替えたんだぜ！**

高速化の数字だけじゃなく、セルフホスティングからネイティブ移植へ舵を切った歴史も、プログラミング好きにはたまらないニュースなんだぜ。
