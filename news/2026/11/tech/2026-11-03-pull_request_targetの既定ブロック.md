# GitHub Actionsのpull_request_target、12月から既定で止まるんだぜ！

- **掲載日**: 2026-11-03
- **発表日**: 2026-11-02
- **区分**: Tech News / GitHub Actions / セキュリティ
- **対象**: GitHub.comの公開リポジトリ

## えっ、CIが突然動かなくなるんだぜ！？

GitHubが2026年11月2日、公開リポジトリの`pull_request_target`イベントを、**2026年12月2日から既定でブロックする**と発表したんだぜ。

これは全ワークフローが停止する話じゃないんだぜ。対象は`pull_request_target`という特定のイベントなんだぜ。もともと11月2日開始予定だった強制適用が、12月2日へ延期されたんだぜ。

## なぜ止めるんだぜ？

`pull_request_target`は、PRの送り先であるベースリポジトリの権限で実行されるんだぜ。場合によってはシークレットにもアクセスできるんだぜ。

だから、外部フォークから来たPRのコードを不用意に実行すると、秘密情報の漏えいやCIの乗っ取りにつながりかねないんだぜ。

便利なイベントだけど、扱いを間違えると危険なんだぜ！

## 事前に止まる日もあるんだぜ

GitHubは強制適用前に、次の時間帯で一時的なブロックを予定しているんだぜ。

- **11月9日 16:00〜18:00 UTC**（日本時間11月10日 01:00〜03:00）
- **11月16日 16:00〜18:00 UTC**（日本時間11月17日 01:00〜03:00）

対象の実行は失敗扱いになり、エラー注釈が付くんだぜ。期間外は評価モードに戻る予定なんだぜ。

## じゃあどうすればいいんだぜ？

GitHubのInsightsで影響を受けるワークフローを確認するんだぜ。

必要のない`pull_request_target`は使わず、どうしても必要な場合はActionsのイベントポリシーで**対象を絞って明示的に許可**できるんだぜ。

対象はGitHub Free、Team、Enterprise Cloudの公開リポジトリなんだぜ。非公開・内部リポジトリとGitHub Enterprise Serverは今回の既定ルールの対象外なんだぜ。

## だからなんだぜ

**PRのチェックが動くのは当たり前、と思っていたら12月に止まるかもしれないんだぜ！**

でも目的は開発の邪魔じゃなくて、外部PRから高権限のCIへ入る危険な経路を減らすことなんだぜ。今のうちにワークフローを点検するぜ！
