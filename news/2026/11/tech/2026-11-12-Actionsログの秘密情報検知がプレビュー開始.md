# GitHub Actionsのログに秘密が漏れたら検知するんだぜ！ ただしプレビューなんだぜ！

- **掲載日**: 2026-11-12
- **出来事の日付**: 2026-11-09（GitHub公式発表日なんだぜ）
- **区分**: Tech News / GitHub Actions・開発セキュリティ
- **対象**: GitHub Secret Scanning / Actions workflow log scanning
- **提供状態**: **公開プレビュー**。対象のGitHub Enterprise Cloud組織でのみ利用可能なんだぜ
- **検証範囲**: GitHub公式Changelogと製品ドキュメントを確認したぜ。実際に秘密を漏らして試験したわけではないんだぜ

## ソースに鍵を書いていないのに漏れるんだぜ！？

2026年11月9日、GitHubが**ActionsのワークフローログをSecret Scanningで検査する機能**を公開プレビューとして発表したんだぜ。

秘密情報をリポジトリにコミットしなければ大丈夫……と思っても、CIのコマンドがAPIキーなどを**実行ログへ出してしまう**ことがあるんだぜ。おいおい、ソースを守ってもログから漏れるのかよ！

今回の機能は、Issue、PR、Wikiなどの検出に加え、**ワークフローが実行完了した後のログ**をチェックするんだぜ。

対応するプロバイダー固有の秘密情報パターンを検出すると、リポジトリのSecret Scanningアラート一覧に表示するぜ。元のログへのリンクをたどれ、対応する種類では鍵の有効性も検査できるんだぜ。

ログを削除しても、検出済みアラートは残るんだぜ。ただし検知は事後対応で、漏えいを未然に防ぐ機能とは別なんだぜ。

## 有効化しなければ動かないんだぜ

このプレビューの対象は、**GitHub Secret ProtectionかGitHub Advanced Securityを利用するGitHub Enterprise Cloudの企業**なんだぜ。データレジデンシーを有効にしたGHE.comも対象に含まれるぜ。

企業の所有者がEnterprise settingsのPoliciesからAdvanced Securityに進み、Actionsログ検査ポリシーを有効化する必要があるんだぜ。**既定は無効**で、ライセンス条件を満たしSecret Scanningが有効なリポジトリで動くんだぜ。

通常のPublicリポジトリ向け無料Secret Scanningが使えるからといって、**今回のログ検査まで全ユーザーへ開放されたわけではない**ぜ。

## まだ何でも見つけられるわけじゃないんだぜ

公式資料は次の制限を明記しているんだぜ。

- **機能の有効化前に完了したログは遡って検査しない**んだぜ
- **プロバイダー固有パターンのみ**で、汎用・カスタム・AI検出パターンは対象外なんだぜ
- **Actionsがすでにマスクした値**はこの追加検査で検出されないんだぜ
- **アラート通知はプレビュー中送られない**から、管理者や担当者が一覧を見に行く必要があるんだぜ

つまり「Secret Scanningを入れたからCIログも全て安全」とは言えないんだぜ。

ログに鍵を出さない設計、最小権限、短期資格情報、OIDCなどの対策は引き続き重要だぜ。漏えいが疑われたら、ログを消すだけでなく資格情報の失効・再発行・利用履歴の調査を優先するんだぜ。

## だからなんだぜ

**CIはソースコード以外のところでも秘密を漏らし得る**んだぜ！

GitHub Actionsログの検査は守る場所を増やす新しい一歩だけど、プレビューの提供条件と検出範囲を把握して使うべきなんだぜ。
