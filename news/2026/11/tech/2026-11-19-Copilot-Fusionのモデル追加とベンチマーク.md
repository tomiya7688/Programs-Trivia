# Copilot Fusion MaxがTerminal-Benchで71.2%だぜ！？ モデル選択とコストの裏側なんだぜ！

- **掲載日（執筆日）**: 2026-11-19
- **出来事の日付**: 2026-11-17（GitHub公式発表）
- **区分**: Tech News
- **対象**: GitHub Copilot Fusion / Terminal-Bench 4.1
- **公開状態**: Fusionの提供拡大。GitHub Mobileはベータ版から展開中

## 何が起きたんだぜ？

「このタスクにはどのモデルを使おう」と毎回選ぶのが当たり前だと思っていたら、**モデルの選択もAI側が引き受ける**ようになってきたんだぜ！

GitHubは2026年11月17日、**Copilot Fusion** の対応画面とモデルを拡大し、公開ベンチマークの結果も公表したんだぜ。

Fusionは単一のLLM名ではなく、タスクごとにモデルと実行方式を決める仕組みなんだぜ。GitHubの説明では、単一モデル、軽いモデルで試してから必要なら強いモデルへ引き上げるCascade、複数モデルの批評を使うCritiqueを使い分けるんだぜ。

## ベンチでは71.2%、でも結果を混同しないんだぜ

GitHubが紹介した**Terminal-Bench 4.1**の公開リーダーボードで、Fusion Maxは**解決率71.2%（95%信頼区間 ±2.9ポイント）**を記録したんだぜ。比較表ではOpus 5.5 MaxとFable 5.2 Maxがともに**65.8%**だったぜ。

同じリーダーボードの報告コストはFusion Maxが約**2.0千ドル**、Opus 5.5が約**4.7千ドル**、Fable 5.2が約**16.5千ドル**なんだぜ。

ただし、これは**Terminal-Bench 4.1の課題群と各エージェント環境で測った結果**なんだぜ。違うハーネス同士の比較を含むから、モデル単体の優劣や、普段の作業における1ドル当たり実装量を直接証明するわけじゃないんだぜ。信頼区間もあるから、数値差だけを過大評価しないぜ。

## どのFusionに何が追加されたんだぜ？

公式発表によるモデル追加は次のとおりなんだぜ。

| Fusionのレベル | 今回追加されたモデル |
| --- | --- |
| **Max** | Claude Sonnet 5.5 |
| **High** | GPT-6.1 Terra |
| **Standard** | MAI-Code-2 |

Fusion Standardは基本的に1モデルで処理し、HighとMaxは課題次第で追加モデルにレビューさせるんだぜ。**常に全モデルを呼ぶという意味じゃない**んだぜ。

選択できる場所も、GitHub.com、最新のVisual Studio、iOS・AndroidのGitHub Mobile**ベータ版**に拡大したぜ。Mobileの通常版への対応は発表時点では今後の予定なんだぜ。

## おいおい、割引もあるけど「常に3割安い」は違うんだぜ

GitHub公式ドキュメントでは、**2026年11月30日まで有料CopilotプランでFusion利用時のモデル料金を30%割り引く**としているんだぜ。

でも、Fusionはモデルを複数呼ぶ場合があるから、単一モデル直指定より**合計AIクレジットが増えることもある**んだぜ。Fusionそのものに別の追加料金はないけど、各モデルの通常料金に従って使用分を計算する仕組みなんだぜ。

使えるモデルは契約プランや組織の管理ポリシーでも変わるぜ。ベンチマークに載ったFusion Maxを全員が同条件で利用できるわけじゃないんだぜ。

## まだ注意点もあるんだぜ

Fusionが捨てた試行でも、ワークスペースに既に行ったファイル編集は自動で巻き戻らない場合があるんだぜ。AIが二度試したから安全、とは思わず、差分をレビューするんだぜ。

また、この数値は**公開されたベンチマークとGitHubの発表を参照したもの**で、Trivaが同条件で再測定したものではないぜ。

## だからなんだぜ

ポイントは**モデルごとの能力比較だけでなく、仕事の途中でモデルを選び直す設計自体が評価対象になった**ことなんだぜ。実運用なら、解決率・推論レベル・使用モデル・実際のクレジット消費をセットで見るんだぜ！
