# Rust 1.100でnever型が10年越しに安定化、依存更新にも待機期間なんだぜ！

- **掲載日（執筆日）**: 2026-11-19
- **出来事の日付**: 2026-11-12（Rust 1.100.0の正式リリース）
- **区分**: Tech News
- **対象**: Rust 1.100.0 / Cargo
- **公開状態**: Stable（正式版）

## 何が起きたんだぜ？

おいおい、Rustの `!` はずっと見かけていたのに、**型として自由に書けるようになるまで10年もかかった**んだぜ！

Rustチームは2026年11月12日に**Rust 1.100.0**を正式公開したんだぜ。今回の大きな変化は、never型 `!` の安定化、独自アロケータAPIの中核、`DropGuard`、そしてCargoで新しく公開された依存パッケージを一定期間待つ仕組みなんだぜ。

更新するなら、既に `rustup` を導入した環境では `rustup update stable` だぜ。

## `!` がいよいよ普通の型引数に書けるんだぜ

never型は「この値は存在しない」「計算が正常な値を返して終わることはない」を表す型なんだぜ。これまでも `-> !` は使えたけど、1.100.0では例えば `Result<T, !>` のように、型の中に直接 `!` を書けるようになったんだぜ。

```rust
fn guaranteed<T>(result: Result<T, !>) -> T {
    let Ok(value) = result;
    value
}
```

しかも標準ライブラリの `Infallible` はnever型の別名になったんだぜ。失敗しない型を表す方法が一つに寄るんだぜ。

**ただし互換性には注意**だぜ。2015・2018・2021 Editionでも「never型のフォールバック」が `()` から `!` に変わったため、一部の既存コードがコンパイルに失敗する可能性があるんだぜ。2024 Editionでは既に変更済みだったぜ。

## アロケータと終了処理も扱いやすくなるんだぜ

`Allocator` トレイトの中核が安定化され、カスタムアロケータを**`Vec` と `Box` などの対応API**で利用できるようになったんだぜ。ただし、すべてのコレクションやメモリ管理APIが一気に安定化されたわけじゃないぜ。

`core::mem::DropGuard` も導入されたんだぜ。スコープを離れる際にクロージャを呼ぶので、パーサの途中失敗で状態を戻す、といったロールバック処理が書きやすくなるんだぜ。正常終了なら `DropGuard::dismiss` で処理を解除できるぜ。

## Cargoは「公開直後の依存」をすぐ取り込まない選択ができるんだぜ

サプライチェーン対策として、Cargoの依存解決に **minimum publish age（公開後の最低経過期間）** が安定導入されたんだぜ。

例えば、プロジェクトや環境の `.cargo/config.toml` にこう書けるぜ。

```toml
[registry]
global-min-publish-age = "3 days"
```

これなら、利用可能な新版があっても公開から3日未満のものを通常の依存解決では避けられるんだぜ。公開直後の悪意あるパッケージが報告される猶予を作る狙いなんだぜ。

でも**万能なセキュリティ対策じゃない**ぜ。公開日時のメタデータがないバージョンには待機制限を適用できず、`cargo install` はこの制限を無視するんだぜ。普通のレビューや依存更新の監査も必要だぜ。

## まだ注意点もあるんだぜ

Cargoの未使用依存警告は、関連する全ビルドターゲットをチェックしないと表示されない場合があるんだぜ。開発依存についても警告されないという制限があるぜ。

また、Cargoのビルドキャッシュ配置も変わったんだぜ。共有ビルドディレクトリや独自の回避策を使っているプロジェクトは回帰テストしてほしいぜ。

この記事はRustチームの公式発表を読んだもので、独自の実機ベンチマークではないんだぜ。

## だからなんだぜ

**型システム、メモリ管理、依存の安全な更新**が一緒に進んだ、実用面でも重要な正式リリースなんだぜ。まずはCIでコンパイル互換性を確かめるんだぜ！
