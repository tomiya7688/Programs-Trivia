# #034 メタデータってな、個人情報を抱えてるし書き換えもできるんだぜ！

写真をSNSへ載せるんだぜ。

画面に名前も住所も映ってないんだぜ。

**よし、個人情報は何もないんだぜ！**

……いやいや、**写真の裏側に撮影場所が書いてあったらどうするんだぜ！？**

ファイルには、見た目だけでは分からない **メタデータ** が入っている場合があるんだぜ。

しかも、その情報は**読めるし、消せるし、書き換えられることもある**んだぜ！

## メタデータってなんだぜ？

ざっくり言えば、**データそのものについてのデータ**なんだぜ。

例えば写真なら「何が写っているか」が主役なんだぜ。その写真に付く撮影日時やカメラの型番、位置情報などがメタデータなんだぜ。

文章なら本文が主役で、作成者名や編集日時、変更履歴などがメタデータになるんだぜ。

| ファイルや仕組み | 入っている場合がある情報 |
| --- | --- |
| 写真（JPEGなど） | 撮影日時、カメラ機種、GPS座標、撮影設定なんだぜ |
| 動画 | 撮影日時、端末・制作ソフト、位置情報などなんだぜ |
| Word / Excel / PowerPoint | 作成者名、最終保存者、コメント、変更履歴、ファイルパスなどなんだぜ |
| PDF | 作成者、作成ソフト、メタデータ、注釈、非表示の情報などなんだぜ |
| Gitのコミット | 作成者名、メールアドレス、日時などなんだぜ |

もちろん、**全部のファイルに全部の項目が入っているわけじゃない**んだぜ。保存形式、端末の設定、ソフト、共有方法によって変わるぜ。

さらに、ファイルの中のEXIF情報と、ファイルシステムが管理する作成・更新日時、クラウドサービス側の記録は**別々の情報**なんだぜ。

## 写真一枚で場所が分かっちゃうことがあるんだぜ

カメラで位置情報の記録を許可していると、写真にGPS座標が関連付けられる場合があるんだぜ。

~~~text
ただの散歩の写真なんだぜ
    ↓
写真ファイルに撮影位置が記録されていたんだぜ
    ↓
その場所が地図で分かる可能性があるんだぜ
    ↓
おいおい、知らない相手に撮影場所を教えてしまったんだぜ！
~~~

Appleの公式説明でも、位置情報メタデータ付きの写真を共有した場合、共有相手が撮影場所を知る可能性があると案内しているんだぜ。

ただし、SNSやメッセージアプリが画像を加工して位置情報を取り除く場合もあるぜ。**どこへ投稿しても必ずGPSが公開される、というわけではない**んだぜ。

逆に「このサービスなら絶対消える」と決めつけるのも危険なんだぜ。

## 文書ってな、著者名や修正の跡も残るんだぜ！

例えばWordの画面で名前が見えなくても、ファイルには**作成者名・最終保存者・コメント・変更履歴**が残っている場合があるんだぜ。

Microsoftはこうした情報を調べて削除するために、**ドキュメント検査（Document Inspector）**を用意しているんだぜ。

Wordなどでは、`ファイル → 情報 → 問題のチェック → ドキュメント検査` から確認できるんだぜ。対応する項目はアプリやバージョンで違うぜ。

PDFでも同じなんだぜ。Adobe Acrobat Proには、メタデータやコメント、非表示レイヤーなどを調べて取り除く**非表示情報の削除**機能があるんだぜ。

**「本文から名前を消したんだぜ！」→「でも文書のプロパティに名前が残ってるんだぜ！」**

……**おいおい、そこも確認するんだぜ！**

なお、隠し文字や埋め込みオブジェクトなどは、単純なメタデータ削除だけで対応できるとは限らないんだぜ。

## 実はメタデータは書き換えられるんだぜ！

これが今回のもう一つのポイントなんだぜ。

例えば写真の **Exif** や **XMP** などの情報は、対応するソフトを使えば編集できるんだぜ。

**ExifTool** というツールなら、写真のメタデータを確認したり、タグを編集・削除したりできるんだぜ。

例えば、インストール済みのExifToolでJPEGを調べるならこうなんだぜ。

```sh
exiftool photo.jpg
```

そして公開用の別ファイルを作りながら、**EXIFのGPSグループ**を削除する例はこうなんだぜ。

```sh
exiftool -GPS:all= -o share.jpg photo.jpg
```

これは元の `photo.jpg` を残しつつ、`share.jpg` を作る例なんだぜ。

ただし **GPSグループを削除しても、XMP側の位置情報や他の個人情報まで必ず消えるとは限らない**んだぜ。公開前に新しいファイルを改めて確認するんだぜ。

また、`-all=` で一括削除する方法もあるけど、画像の色の情報まで消えて見た目が変わったり、一部の形式ではファイルの処理に支障が出たりする可能性があるぜ。**何でも全部消せばいいわけじゃない**んだぜ。

## じゃあメタデータは証拠にならないんだぜ？

ここで逆方向のトリビアなんだぜ。

**書き換えられるものを、絶対に正しい証拠だと思ってはいけない**んだぜ。

例えば「撮影日時が○月○日なんだぜ」という値が入っていても、それを編集できるなら、**その日時に本当に撮ったという保証にはならない**んだぜ。

ただし、メタデータが全部無価値というわけではないんだぜ。撮影の整理、検索、著作権表示、業務の記録にはとても便利なんだぜ。

大切なのは、**便利な付加情報と、改ざんされていないことの証明は別**だという点なんだぜ。

必要なら電子署名や別の記録と突き合わせて検証するんだぜ。

## Gitにも名前やメールアドレスがあるんだぜ！

プログラマーなら、これも見逃せないんだぜ。

Gitのコミットにも、**authorの名前やメールアドレス、日時**が付いているんだぜ。

GitHubでは、コミット用メールアドレスに **`noreply` アドレス**を使って個人のメールアドレスを公開しない設定ができるんだぜ。

ただし、**今から設定を変えても、過去のコミットに記録されたメールアドレスが自動で書き換わるわけではない**んだぜ。

そしてGitの履歴を書き換えるのは、共有リポジトリのコミットIDや共同作業に影響するから、普通のファイルのタグ編集とは話が違うんだぜ。

## 「消したから大丈夫！」が一番危ないんだぜ

一番気をつけたいのはここなんだぜ。

ファイルのメタデータを変更しても、

- **すでに送った相手のコピー**はそのまま残り得るんだぜ。
- **クラウドの版履歴やバックアップ**にも以前の情報が残り得るんだぜ。
- **サムネイル、埋め込みファイル、本文や画像に写り込んだ情報**は別に確認が必要なんだぜ。
- **ファイルシステムの日時や、公開サービス側のログ**は、ファイル内のEXIFを消しただけでは消えないんだぜ。

だから公開前の手順は、

~~~text
まずファイルを複製するんだぜ
    ↓
必要なメタデータを確認するんだぜ
    ↓
不要な情報を編集・削除するんだぜ
    ↓
公開する方のコピーをもう一度検査するんだぜ
    ↓
そのコピーだけ共有するんだぜ！
~~~

という考え方が安全なんだぜ。

iPhoneなら共有時に **「オプション」から位置情報をオフ**にする方法もあるんだぜ。用途に合った方法を使うんだぜ。

## だからなんだぜ

**ファイルには、表に見えている以上の情報が入っていることがあるんだぜ！**

しかも、そうした情報の一部は簡単に書き換えられるんだぜ。

それって二つの意味で大事なんだぜ。

**プライバシーを守りたいなら、公開前に見えない情報も確認する。**

**情報の正しさを調べたいなら、メタデータを無条件に信用しない。**

**「何も写ってないから安心なんだぜ！」→「撮影場所がファイルに書いてあったんだぜ！」**

……**これは大変だぜ！ 見えないところまで気を配るんだぜ！**
