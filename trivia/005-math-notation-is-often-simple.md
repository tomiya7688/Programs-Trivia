# #005 プログラムの説明に出てくる数式ってな、数学に戻すとすげーしょうもないことが多いんだぜ

プログラミングとかAIの説明を読んでると、急に数式が出てくるんだぜ。

```text
f(x)
Σ
e^x
max(0, x)
```

このへんが並び始めると、

> **なんか急に高度な数学が始まったんだぜ**

って気分になるんだぜ。

でもな。

**記号を日本語に戻してみると、やってること自体はびっくりするくらい単純だったりするんだぜ。**

### ReLUなんて「マイナスなら0、それ以外はそのまま」なんだぜ

ニューラルネットワークでよく出てくる **ReLU関数** は、

```text
ReLU(x) = max(0, x)
```

なんだぜ。

数式で書くとそれっぽいんだぜ。

でも日本語にすると、

```text
xがマイナスなら0なんだぜ
それ以外ならxをそのまま返すんだぜ
```

なんだぜ。

コードにすると、

```python
def relu(x):
    return max(0, x)
```

なんだぜ。

もっと露骨に書けば、

```python
def relu(x):
    if x < 0:
        return 0
    return x
```

なんだぜ。

急にしょうもなく見えてくるんだぜ。

### シグマも「全部足すんだぜ」なんだぜ

数学でよく出てくる、

```text
Σ
```

も見た目は強そうなんだぜ。

でもだいたい意味は、

> **決められた範囲を全部足すんだぜ**

なんだぜ。

例えば、

```text
Σ xᵢ
```

なら、プログラムではかなり雑に、

```python
total = 0

for x in values:
    total += x
```

なんだぜ。

つまり **for文で足してるだけなんだぜ。**

### 平均二乗誤差も名前ほど怖くないんだぜ

機械学習でよく見る **平均二乗誤差、MSE** は、

```text
MSE = (1/n) Σ (y - ŷ)²
```

みたいに書くんだぜ。

でも日本語にすると、

```text
正解と予測の差を出すんだぜ
↓
二乗するんだぜ
↓
全部足すんだぜ
↓
個数で割るんだぜ
```

なんだぜ。

やってることはかなり素朴なんだぜ。

### 内積も「掛けて足すんだぜ」なんだぜ

ベクトルの内積、

```text
a · b
```

もAIやグラフィックスでは大量に出てくるんだぜ。

でも中身は、

```text
a₁b₁ + a₂b₂ + a₃b₃ + ...
```

なんだぜ。

つまり、

> **同じ場所の数字を掛けて、最後に全部足すんだぜ。**

なんだぜ。

これもコードにするとループなんだぜ。

### 数式が難しいんじゃなくて、圧縮率が高いんだぜ

ここが大事なんだぜ。

数式がしょうもないと言っても、数学が無意味って話じゃないんだぜ。

むしろ逆なんだぜ。

例えば、

```text
MSE = (1/n) Σ (yᵢ - ŷᵢ)²
```

だけで、

```text
全データについて
正解と予測値の差を取って
それを二乗して
全部合計して
データ数で割るんだぜ
```

を一行で書けるんだぜ。

**数式は難しいことを書くためのものというより、処理をものすごい密度で圧縮して書く記法なんだぜ。**

だから慣れてないと、

> **難しいことをやってるんだぜ**

に見えるんだけど、

一個ずつ展開すると、

> **足すんだぜ**
>
> **掛けるんだぜ**
>
> **大きい方を取るんだぜ**

だったりするんだぜ。

### もちろん本当に難しい数式もあるんだぜ

ここは言っておくんだぜ。

世の中の数式が全部簡単なわけじゃないんだぜ。

証明も理論も、本当に難しいものはいくらでもあるんだぜ。

でもプログラムや機械学習の入門説明で出てくる数式のかなりの部分は、

**記号の読み方が分からないせいで、実際の処理以上に難しく見えてる**

ことがあるんだぜ。

だから数式を見てビビったら、

> **これコードにすると何行なんだぜ？**

って考えるといいんだぜ。

ReLUなんて、

```python
max(0, x)
```

で終わりなんだぜ。

**数式の威圧感と、処理の難しさは別物なんだぜ。**
