# #023 暗号化ってな、仕組みそのものは意外と単純なんだぜ

暗号って聞くと、

> **ものすごく複雑な数学でグチャグチャにしてるんだぜ。**

みたいな印象があるんだぜ。

でもな。

**暗号化の基本操作そのものは、意外と素朴なんだぜ。**

難しいのは、

> **その素朴な操作を、攻撃されても破れない形に組み合わせることなんだぜ。**

なんだぜ。

## 一番単純な暗号なら、本当に足し算みたいなもんなんだぜ

例えばシーザー暗号なんだぜ。

```text
A → D
B → E
C → F
```

みたいに、文字を一定数ずらすんだぜ。

つまり、

```text
文字の番号 + 3
```

くらいなんだぜ。

これはもちろん今では安全じゃないんだぜ。

でも、

> **暗号化 = 情報を規則に従って別の形へ変えるんだぜ。**

という本質はちゃんと入ってるんだぜ。

## XORだけでも暗号っぽいことはできるんだぜ

コンピュータの暗号では **XOR** がよく出てくるんだぜ。

例えば、

```text
平文:  10110010
鍵:    01101100
----------------
暗号文:11011110
```

みたいにするんだぜ。

同じ鍵でもう一度XORすると、

```text
暗号文:11011110
鍵:    01101100
----------------
平文:  10110010
```

に戻るんだぜ。

つまり、

> **同じ鍵でXORするだけなんだぜ。**

なんだぜ。

ものすごく単純なんだぜ。

### でも鍵の使い方を間違えると終わるんだぜ

ここが暗号の難しいところなんだぜ。

XORが単純だからダメなんじゃないんだぜ。

**鍵の使い方次第なんだぜ。**

One-Time Padなら、

```text
鍵が完全にランダムなんだぜ
平文と同じ長さなんだぜ
一度しか使わないんだぜ
```

という条件を守れば、理論上は完全秘匿なんだぜ。

逆に同じ鍵を再利用したら、

```text
暗号文A XOR 暗号文B
```

から鍵が消えて、平文同士の関係が見えてくるんだぜ。

つまり、

> **操作は単純でも、運用ルールを間違えると一気に弱くなるんだぜ。**

なんだぜ。

## AESだって、中身は小さい操作の繰り返しなんだぜ

現代の代表的な共通鍵暗号 **AES** も、

> **謎の超複雑数式を一発で計算するんだぜ。**

ではないんだぜ。

ざっくり言えば、

```text
byteを置き換えるんだぜ
行をずらすんだぜ
列を混ぜるんだぜ
鍵とXORするんだぜ
```

みたいな処理を何roundも繰り返すんだぜ。

FIPS 197でも、

```text
SubBytes
ShiftRows
MixColumns
AddRoundKey
```

という構造で定義されてるんだぜ。

一個一個の操作を見ると、

> **意外と地味なんだぜ。**

なんだぜ。

でも、その順番と回数と数学的性質をうまく組み合わせることで、

**入力の1bitを変えただけでも出力全体が大きく変わる**

ように作られてるんだぜ。

## RSAも「でかい数で累乗して余りを取る」なんだぜ

公開鍵暗号になると急に難しそうなんだぜ。

RSAなんて、

```text
c = m^e mod n
```

みたいな式が出てくるんだぜ。

でも日本語にすると、

> **ものすごく大きい数で累乗して、nで割った余りを取るんだぜ。**

なんだぜ。

復号側も別の指数を使って、

```text
m = c^d mod n
```

なんだぜ。

もちろん、その鍵をどう作るかには素数や数論が出てくるんだぜ。

でも処理の骨格だけ見ると、

**巨大整数の掛け算と剰余演算なんだぜ。**

なんだぜ。

## 難しいのは「暗号そのもの」より周りなんだぜ

暗号実装で本当に怖いのは、

```text
鍵をどう作るんだぜ
鍵をどこに保存するんだぜ
nonceを使い回してないんだぜ
乱数はちゃんとしてるんだぜ
paddingは安全なんだぜ
改ざん検知してるんだぜ
side-channelは大丈夫なんだぜ
error messageから情報が漏れないんだぜ
```

みたいなところなんだぜ。

つまり、

> **暗号アルゴリズムを理解したんだぜ。**

と、

> **安全な暗号システムを作れるんだぜ。**

は全然違うんだぜ。

### 暗号化だけでは改ざんを防げないんだぜ

ここも重要なんだぜ。

暗号化すると、

> **内容を読みにくくできるんだぜ。**

なんだぜ。

でも、

> **書き換えられてないんだぜ。**

までは自動では保証されないんだぜ。

だから今は、

```text
AES-GCMなんだぜ
ChaCha20-Poly1305なんだぜ
```

みたいな **Authenticated Encryption** を使うことが多いんだぜ。

こいつらは、

```text
秘密にするんだぜ
+
改ざんも検知するんだぜ
```

を一緒にやるんだぜ。

つまり、

> **暗号化だけすれば安全なんだぜ。**

でもないんだぜ。

## 自作暗号が危ないのは、操作が難しいからじゃないんだぜ

よく、

> **暗号は自作するななんだぜ。**

って言われるんだぜ。

これは、

> **数学が難しすぎて一行も書けないんだぜ。**

という意味じゃないんだぜ。

むしろ逆なんだぜ。

処理そのものは簡単に書けるから、

```python
for i in range(len(data)):
    data[i] ^= key[i % len(key)]
```

みたいなのを作って、

> **暗号できたんだぜ。**

となりやすいんだぜ。

でも、

```text
鍵の再利用なんだぜ
既知平文攻撃なんだぜ
統計的偏りなんだぜ
nonceなんだぜ
認証なんだぜ
side-channelなんだぜ
```

まで考えると、一気に難しくなるんだぜ。

**暗号の怖さは、コードが短く書けることと、安全であることが全然別なところなんだぜ。**

## だからなんだぜ

暗号化を見て、

> **ものすごく複雑な魔法なんだぜ。**

と思う必要はないんだぜ。

中身を分解すると、

```text
足すんだぜ
XORするんだぜ
置き換えるんだぜ
並べ替えるんだぜ
混ぜるんだぜ
累乗するんだぜ
余りを取るんだぜ
```

みたいな操作の組み合わせなんだぜ。

でも、

**簡単な操作を組み合わせて、攻撃者が何をしても破れないようにする。**

そこが難しいんだぜ。

> **暗号は、複雑な計算をする技術じゃないんだぜ。**
>
> **単純な計算を、壊れないように組み合わせる技術なんだぜ。**
